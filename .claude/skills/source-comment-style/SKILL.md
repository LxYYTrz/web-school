# 源码注释约定

用户的讲解顺序是整体 PPT、通信等专题、源码文件。注释应让讲解者打开文件后知道它在项目中的位置，进入函数后能顺着输入、处理、输出和后续调用讲下去。

## 四层说明

1. 文件开头说明运行位置、文件职责、主要入口、实际处理顺序及相关文件。方法的排列不等于执行顺序；启动钩子、消息回调、请求入口要分别说明。
2. 函数或独立功能段之前，说明谁调用、输入来自哪里、本段完成什么。小型类型或模块文件用简短说明即可，不强制凑齐模板。
3. 关键有效语句下面保留两行：第一行解释实际业务动作及结果，第二行解释局部变量、方法、参数的来源和作用。标识符首次出现时讲清，后续结合当前用途说明，避免反复列词典。
4. 功能结束处在有必要时交代返回值、保存位置、接收方或失败分支。不在每个括号后重复“结束函数”，不重复段前已有结论，也不把定义函数说成已经执行成功。

## 内容必须查证

- 区分项目方法、框架注入服务、第三方库 API、语言内置方法和报文字段。不用“调用方法”“设置变量”“供后续使用”等空话代替解释。
- 同名变量按当前作用域说明。消息的设备编码和数据库内部编号、遥测角度数组和 Three.js 节点数组不是同一种数据。
- 地址、单位、周期、权限与状态必须符合配置和实现。区分默认配置、运行输入与尚未核实的现场状态；不把目标周期写成实际恒定频率。
- 外层调用说明任务交给谁，内部方法解释实际步骤。跨文件按仓库相对路径和函数名指引，不写固定行号或某份 PPT 的页码。
- 说明失败分支的具体影响，不把消息确认、写响应、历史入队或接口返回扩大成物理动作完成或持久保存。
- 保留有效的契约、公式、例子与说明；纠正过时、错误的旧注释；删除或合并重复套话及错误套用的类型信息。

## 示例

```ts
// MQTT 接入服务把已校验的机器人整帧交给这里，保存稍后首屏请求需要的最新状态。
// lineId、deviceId 是业务编码；frame 是整帧对象，同一设备使用固定 key 覆盖旧值。
setRobotFrame(lineId: string, deviceId: string, frame: unknown) {
  this.redis
    .set(`rt:${lineId}:robot:${deviceId}`, JSON.stringify(frame), 'EX', 60)
    // 把整帧写入该设备固定的 Redis key，并从本次成功写入重新计算 60 秒有效期。
    // set 来自 ioredis，JSON.stringify 是内置编码方法；EX 的单位是秒，过期不主动清空浏览器已有帧。
    .catch((e: Error) => this.logger.error(`写机器人快照失败: ${e.message}`));
    // 写入失败时记录错误，历史与实时推送路径分别处理各自的结果。
    // e 是本次 Redis 异步写入的异常；logger 是 NestJS 日志工具，这里不补写历史或重发网页事件。
}
```

## 修改范围与验证

- 只修改手写源码注释，不调整业务语句、方法排列、配置值和接口契约。不另造脱离源码的逐行说明文件。
- 生成目录、依赖、锁文件不加教学注释；严格 JSON、CSV 不插入非法注释，解释写在使用这些数据的源码中。
- 保留编码、换行和必要的 UTF-8 BOM；shebang、doctype、类型及工具指令保留位置。不将注释插入 SQL、模板字符串、HTML 属性或显式续行中。
- 比较 JS/TS/Python 去注释语法树、Vue 模板编译结果及样式，检查 PowerShell token 和配置有效语句，确认行为未变。人工核对来源和调用关系，语法检查不能替代事实检查。
- 行号变化后核对 PPT 与讲稿链接，指向对应功能说明或实现入口；固定提交链接应确认对应提交已推送。
