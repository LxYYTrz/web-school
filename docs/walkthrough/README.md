# walkthrough/ —— 汇报讲解材料

> 两篇配套文档，**顺序固定**：先《代码讲解》（展示用），后《讲稿》（演讲者自用）。
> 写作规范见 [`../../.claude/skills/code-walkthrough-script/SKILL.md`](../../.claude/skills/code-walkthrough-script/SKILL.md)。

---

## 1. 两篇是什么

| | 《代码讲解》 | 《讲稿》 |
|---|---|---|
| 定位 | **展示用** —— 投屏给听众看的 | **演讲者自用** —— 自己照着念的 |
| 内容 | 代码结构事实：有什么文件、各自干什么 | 嘴上说的话 + 此刻该看哪儿 |
| 形态 | 目录 → 文件 → 职责，逐条展开 | 两栏对照表：`屏幕显示` \| `你说` |
| 用词 | 项目自己的客观术语（"四个域""编排"） | 讲给听众听的通俗话（"四个问题"） |

> ⚠ **两篇允许用不同说法，不要强行统一。**
> 讲稿把"四个域"翻译成"四个问题"是**演讲技巧**；但不要为了统一口径去改《代码讲解》的术语。
> （这条是 SKILL.md 里记的踩坑，别再犯。）

## 2. 仓库副本 vs 飞书版

| | 位置 | 角色 |
|---|---|---|
| 飞书云文档 | [代码讲解](https://bcnvmiga7m0x.feishu.cn/wiki/K1ruwhmumiHABTkQqW2cEbw3nTf) / [讲稿](https://bcnvmiga7m0x.feishu.cn/wiki/VwDawXJURiVEAtkmnvQcFbLdnCg) | **现场投屏用的那一份**（块 id 定位都记在那儿） |
| 本目录 | `代码讲解.md` / `讲稿.md` | **仓库副本** —— 可版本化、可 review、可全文搜索 |

**改哪边**：内容以飞书版为准；代码改动后，先改飞书，再把本目录同步回来（一起提交）。
⚠ **不要 overwrite 整篇** —— 讲稿是多模块累积的，新增模块用 `append`（见 SKILL.md「写飞书文档」）。

## 4. 为什么仓库里也要存一份

- 飞书文档不在版本控制里，**改了什么没人 review**，现场讲错也没法追溯。
- 仓库这份能 `git diff` 出"这次讲解稿跟着代码改了哪几句"。
- 交接给不熟悉飞书的同事时，`docs/walkthrough/` 是唯一入口。
