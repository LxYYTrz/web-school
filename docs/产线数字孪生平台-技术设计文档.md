## 1. 项目背景与目标

### 1.1 需求概述

建设一个外部 Web 网站，实现：

1. **实时数据采集**：从产线 PLC 获取机器人六轴数据及产线状态数据
2. **数字孪生展示**：前端实时呈现机器人运动状态（简化版孪生，非高精度物理仿真）
3. **机器视觉展示**：视觉工控机拍摄的照片上传至云端，前端可查看
4. **角色权限控制（RBAC）**：
   - 产线操作员：可查看 + 控制产线
   - 客户：仅可查看产线状态（公开数据）
   - 数据分析员：可查看详细数据及非公开数据
   - 管理员：全功能 + 用户管理
5. **可演进**：前期用模拟数据开发全链路，进场后仅替换数据采集层即可投产

### 1.2 环境约束

| 项 | 结论 |
|---|---|
| 云服务器 | Linux，公网可达 |
| 工控机 | Windows（PLC 侧 + 视觉侧） |
| 网络 | 产线局域网内部互通；产线 → 云端走公网 |
| 团队语言偏好 | 无强制，按最优选型 |

### 1.3 核心设计原则

1. **数据模型先行**：先冻结统一数据契约，前后端、采集层都按契约开发
2. **采集层适配器模式**：Mock 采集器与真实采集器实现同一接口，进场后只换实现
3. **边缘轻、云端重**：工控机只跑轻量采集 Agent，业务逻辑全部在云端
4. **单向出站**：工控机只主动向外连接，云端永不主动连入产线，防火墙不开入站端口

## 2. 总体架构

### 2.1 架构图

```
┌────────────────────────── 产线局域网 ──────────────────────────┐
│                                                                 │
│   PLC ──(OPC UA / Modbus TCP / S7)──▶ 边缘Agent (工控机A, Win)  │
│                                                                 │
│   视觉相机/软件 ──(图片文件/HTTP/SDK)─▶ 边缘Agent (工控机B, Win) │
│                                                                 │
│   说明：Agent 是轻量采集转发程序，不含业务逻辑，不连数据库         │
└──────────────────────────────┬──────────────────────────────────┘
                               │ MQTT over TLS (8883) + HTTPS (443)
                               │ 仅出站，断网本地缓存续传
                               ▼
┌──────────────────────── 云服务器 (Linux, Docker Compose) ──────┐
│                                                                 │
│   nginx ──▶ 前端静态文件 / 反向代理后端 API / WSS                │
│   backend (NestJS) ── 业务API + WebSocket推送 + 消费MQTT         │
│   emqx ── MQTT Broker (8883 TLS, 每机独立凭证 + ACL)             │
│   postgres (+TimescaleDB) ── 业务表 + 时序表                     │
│   redis ── 设备最新状态缓存 / 会话                               │
│   minio ── 视觉图片对象存储（不对公网暴露）                       │
│                                                                 │
└──────────────────────────────┬──────────────────────────────────┘
                               │ HTTPS (443) + WSS
                               ▼
                    浏览器（操作员 / 客户 / 分析员 / 管理员）
```

### 2.2 数据流向

**上行（遥测）**：

```
PLC/相机 → Agent采集 → 统一消息格式 → MQTT(TLS) → EMQX
→ backend订阅消费 → ①写TimescaleDB(历史) ②写Redis(最新值) ③WebSocket推给在线前端
图片：Agent → HTTPS上传 → backend → MinIO存储 + vision_images表记录
```

**下行（控制）**：

```
前端操作 → backend鉴权(requirePermission) → 生成指令(带签名+时间戳)
→ MQTT下行主题 → Agent校验签名 → 写PLC → 执行结果回传 → operation_logs留痕
```

### 2.3 为什么不是"每个工控机一个完整后端"

- 完整后端意味着数据库连接、业务逻辑、权限判断分散到产线侧，升级和排障都困难
- Agent 模式：产线侧只有一个几百行的采集转发程序，崩溃/断网影响面小，支持本地缓存续传
- 新增产线 = 再部署一个 Agent，云端零改动

## 4. 网络与安全设计（公网方案）

### 4.1 端口暴露策略

| 端口 | 服务 | 暴露范围 |
|---|---|---|
| 80 | nginx（跳转 443） | 公网 |
| 443 | nginx（HTTPS + WSS） | 公网 |
| 8883 | EMQX（MQTT over TLS） | 公网（仅 Agent 连接） |
| 5432 / 6379 / 9000 | PG / Redis / MinIO | 仅 Docker 内网，不暴露 |
| 22 | SSH | 建议改端口 + 密钥登录 + fail2ban |

### 4.2 硬性安全要求

1. **MQTT 必须 TLS**，禁止 1883 明文端口对外
2. **每台 Agent 独立 MQTT 账号**，EMQX ACL 限制：
   - 只允许发布 `factory/{自己的产线}/#`
   - 只允许订阅 `factory/{自己的产线}/cmd/#`
   - 一台被攻破不影响其他产线
3. **工控机防火墙**：只放行出站 8883/443，无任何入站规则
4. **控制指令防重放**：指令包含时间戳 + HMAC 签名，Agent 校验时间窗口（±30s）与签名
5. **全站 HTTPS/WSS**，JWT 有效期 2h + Refresh Token 7d
6. **所有控制操作写 operation_logs 审计表**
7. SSH 密钥登录、禁用 root 密码登录、fail2ban

### 4.3 推荐增强（可选）：Tailscale 组网

将云服务器与各工控机加入同一 Tailscale 虚拟内网，MQTT/API 流量走加密隧道，云服务器可不对公网暴露 8883。配置约半小时，安全等级显著提升。**建议实施**。

## 5. 数据契约（冻结，所有端遵守）

### 5.1 MQTT 主题设计

```
上行：
factory/{lineId}/telemetry/{deviceId}      遥测数据（关节角、状态量）
factory/{lineId}/status/{deviceId}         设备状态变化（运行/停止/故障）
factory/{lineId}/alarm/{deviceId}          报警事件
factory/{lineId}/agent/heartbeat           Agent 心跳（10s）
factory/{lineId}/agent/lwt                 Agent 遗嘱（离线通知，retained）

下行：
factory/{lineId}/cmd/{deviceId}            控制指令
factory/{lineId}/cmd/ack                   指令执行回执
```

### 5.2 消息格式

**遥测（机器人六轴）**：

```json
{
  "deviceId": "robot01",
  "ts": 1759900000000,
  "type": "robot.joints",
  "payload": {
    "j1": 12.5, "j2": -30.2, "j3": 45.0,
    "j4": 0.1,  "j5": 88.0,  "j6": 10.0,
    "status": "running",
    "program": "P_023",
    "speedOverride": 80
  }
}
```

**报警**：

```json
{
  "deviceId": "robot01",
  "ts": 1759900000000,
  "type": "alarm",
  "payload": { "level": "warning", "code": "E1024", "message": "关节2温度偏高" }
}
```

**控制指令（下行）**：

```json
{
  "cmdId": "uuid-v4",
  "deviceId": "robot01",
  "ts": 1759900000000,
  "action": "line.stop",
  "params": {},
  "operator": "zhangsan",
  "sig": "HMAC-SHA256(指令体, 设备密钥)"
}
```

**回执**：

```json
{ "cmdId": "uuid-v4", "ts": 1759900000100, "result": "ok", "message": "" }
```

### 5.3 视觉图片上传（HTTPS，不走 MQTT）

```
POST /api/vision/images
Header: X-Agent-Id, X-Agent-Token, X-Signature
Body: multipart/form-data { image, meta: { deviceId, ts, triggerType, result } }

响应: { "imageId": 123, "url": "/api/vision/images/123/file" }
```

- 图片经后端写入 MinIO，元数据写 `vision_images` 表
- 前端通过后端签发的临时 URL 访问，MinIO 不对公网暴露

### 5.4 频率策略

| 数据 | 采集/推送频率 | 入库频率 |
|---|---|---|
| 六轴数据（孪生用） | 10~20 Hz 推送前端 | 降采样 1~2 Hz 入时序库 |
| 设备状态/报警 | 事件触发 | 全量入库 |
| 视觉图片 | 按拍摄触发 | 原图存 MinIO |
| 心跳 | 10 s | 不入库，只更新 Redis |

## 6. 数据库设计（PostgreSQL 16 + TimescaleDB）

```sql
-- ============ 权限域 ============
CREATE TABLE users (
  id            BIGSERIAL PRIMARY KEY,
  username      VARCHAR(64) UNIQUE NOT NULL,
  password_hash VARCHAR(128) NOT NULL,
  display_name  VARCHAR(64),
  status        SMALLINT NOT NULL DEFAULT 1,      -- 1启用 0禁用
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE roles (
  id   BIGSERIAL PRIMARY KEY,
  code VARCHAR(32) UNIQUE NOT NULL,               -- admin/operator/viewer/analyst
  name VARCHAR(64) NOT NULL
);

CREATE TABLE permissions (
  id   BIGSERIAL PRIMARY KEY,
  code VARCHAR(64) UNIQUE NOT NULL,               -- line:view / line:control / data:detail ...
  name VARCHAR(64) NOT NULL
);

CREATE TABLE role_permissions (
  role_id       BIGINT REFERENCES roles(id) ON DELETE CASCADE,
  permission_id BIGINT REFERENCES permissions(id) ON DELETE CASCADE,
  PRIMARY KEY (role_id, permission_id)
);

CREATE TABLE user_roles (
  user_id BIGINT REFERENCES users(id) ON DELETE CASCADE,
  role_id BIGINT REFERENCES roles(id) ON DELETE CASCADE,
  PRIMARY KEY (user_id, role_id)
);

-- 预置权限编码
-- line:view         查看产线状态（所有角色）
-- line:control      控制产线（operator, admin）
-- data:detail       查看详细/非公开数据（analyst, admin）
-- alarm:ack         报警确认（operator, admin）
-- vision:view       查看视觉图片（operator, analyst, admin；客户不可见）
-- admin:user        用户与角色管理（admin）

-- ============ 设备/产线域 ============
CREATE TABLE production_lines (
  id       BIGSERIAL PRIMARY KEY,
  code     VARCHAR(32) UNIQUE NOT NULL,           -- line01
  name     VARCHAR(64) NOT NULL,
  location VARCHAR(128),
  status   SMALLINT NOT NULL DEFAULT 1
);

CREATE TABLE devices (
  id      BIGSERIAL PRIMARY KEY,
  line_id BIGINT REFERENCES production_lines(id),
  code    VARCHAR(32) NOT NULL,                   -- robot01 / camera01 / plc01
  name    VARCHAR(64),
  type    VARCHAR(16) NOT NULL,                   -- robot / camera / plc
  model   VARCHAR(64),
  meta    JSONB,                                  -- 厂商、轴数、IP 等扩展信息
  status  SMALLINT NOT NULL DEFAULT 1,
  UNIQUE (line_id, code)
);

-- ============ 时序数据域（TimescaleDB）============
CREATE TABLE telemetry (
  ts           TIMESTAMPTZ NOT NULL,
  device_id    BIGINT NOT NULL REFERENCES devices(id),
  metric       VARCHAR(32) NOT NULL,              -- j1..j6 / temperature / current ...
  value_double DOUBLE PRECISION,
  value_text   TEXT,
  quality      SMALLINT DEFAULT 1                 -- 1好 0坏
);
SELECT create_hypertable('telemetry', 'ts');
CREATE INDEX idx_telemetry_dev_metric_ts ON telemetry (device_id, metric, ts DESC);
-- 保留策略示例：SELECT add_retention_policy('telemetry', INTERVAL '90 days');
-- 连续聚合示例：按 1min 平均做降采样视图，供历史曲线快速查询

CREATE TABLE device_status (
  ts        TIMESTAMPTZ NOT NULL,
  device_id BIGINT NOT NULL REFERENCES devices(id),
  status    VARCHAR(16) NOT NULL,                 -- running/idle/stopped/fault/offline
  program   VARCHAR(64),
  extra     JSONB
);
SELECT create_hypertable('device_status', 'ts');

-- ============ 事件/报警域 ============
CREATE TABLE alarms (
  id        BIGSERIAL PRIMARY KEY,
  ts        TIMESTAMPTZ NOT NULL,
  device_id BIGINT REFERENCES devices(id),
  level     VARCHAR(16) NOT NULL,                 -- info / warning / critical
  code      VARCHAR(32),
  message   TEXT,
  status    VARCHAR(16) NOT NULL DEFAULT 'active',-- active / acked / resolved
  ack_by    BIGINT REFERENCES users(id),
  ack_at    TIMESTAMPTZ
);
CREATE INDEX idx_alarms_ts ON alarms (ts DESC);

-- ============ 视觉图片域（文件在 MinIO）============
CREATE TABLE vision_images (
  id           BIGSERIAL PRIMARY KEY,
  ts           TIMESTAMPTZ NOT NULL,              -- 拍摄时间
  device_id    BIGINT REFERENCES devices(id),
  line_id      BIGINT REFERENCES production_lines(id),
  bucket       VARCHAR(64) NOT NULL,
  object_key   VARCHAR(256) NOT NULL,             -- line01/2026/10/08/xxx.jpg
  trigger_type VARCHAR(32),                       -- 拍照触发类型
  result       JSONB,                             -- 视觉判定结果（OK/NG、缺陷坐标等）
  width        INT,
  height       INT,
  size_bytes   BIGINT
);
CREATE INDEX idx_vision_images_ts ON vision_images (ts DESC);
CREATE INDEX idx_vision_images_device_ts ON vision_images (device_id, ts DESC);

-- ============ 操作审计域 ============
CREATE TABLE operation_logs (
  id      BIGSERIAL PRIMARY KEY,
  ts      TIMESTAMPTZ NOT NULL DEFAULT now(),
  user_id BIGINT REFERENCES users(id),
  action  VARCHAR(64) NOT NULL,                   -- line.start / line.stop / alarm.ack ...
  target  VARCHAR(64),                            -- line01/robot01
  params  JSONB,
  result  VARCHAR(16),                            -- ok / denied / failed
  ip      INET
);

-- ============ 数据源配置域（Mock/真实切换）============
CREATE TABLE data_source_configs (
  id          BIGSERIAL PRIMARY KEY,
  line_id     BIGINT REFERENCES production_lines(id),
  source_type VARCHAR(16) NOT NULL,               -- mock / opcua / modbus / s7
  config      JSONB NOT NULL,                     -- 连接参数（Agent 启动时拉取或本地覆盖）
  enabled     BOOLEAN NOT NULL DEFAULT true
);
```

**RBAC 关键约束**：权限判断全部在后端中间件（`requirePermission('line:control')`），前端只按权限隐藏按钮，不做安全边界。

## 7. 云端后端设计（NestJS）

### 7.1 模块划分

```
server/src
├── main.ts
├── config/                # 配置加载（环境变量）
├── auth/                  # 登录、JWT 签发/刷新、密码哈希(argon2)
├── users/                 # 用户/角色/权限管理（admin）
├── lines/                 # 产线、设备 CRUD
├── telemetry/             # 时序数据查询 API（历史曲线）
├── realtime/              # MQTT 消费 + WebSocket 网关（核心）
│   ├── mqtt.service.ts    # 订阅 EMQX 上行主题，分发处理
│   ├── ws.gateway.ts      # 按 lineId 分房间推送，连接时鉴权
│   └── latest.service.ts  # 最新状态写 Redis，首屏直读
├── alarms/                # 报警查询、确认
├── vision/                # 图片上传（Agent）、图片列表/访问（前端，权限 vision:view）
├── control/               # 控制指令 API：鉴权→签名→发MQTT下行→等回执→写审计
├── audit/                 # 操作日志查询
└── common/                # 权限装饰器、拦截器、过滤器、DTO
```

### 7.2 实时链路细节

- 前端 WebSocket 连接时携带 JWT，网关校验后按角色 + 产线加入对应 room
- MQTT 消费端收到遥测后三路处理：批量入库（每 1s 攒批写 PG）、更新 Redis（`latest:{deviceId}`）、WS 推送到对应 room
- 客户角色的 WS 连接只推送状态类消息，不推送详细工艺数据（服务端过滤，不靠前端）

```
GET    /api/telemetry/history     ?deviceId=&metric=&from=&to=&agg=1m
```

## 8. 边缘 Agent 设计（Python，Windows 工控机）

### 8.1 目录结构

```
agent/
├── main.py                 # 入口：加载配置、启动各采集器、MQTT客户端
├── config.yaml             # 产线编号、云端地址、凭证、采集点表
├── core/
│   ├── mqtt_client.py      # 连接/重连/TLS/LWT/离线队列
│   ├── offline_queue.py    # SQLite 本地缓存，恢复后按序补传
│   ├── heartbeat.py        # 10s 心跳
│   ├── command_handler.py  # 下行指令：验签 → 执行 → 回执
│   └── watchdog.py         # 异常捕获 + 进程自愈
├── collectors/
│   ├── base.py             # 抽象接口：read() -> TelemetryMessage
│   ├── mock_collector.py   # 模拟六轴数据（正弦+噪声+偶发报警）★ 现在实现
│   ├── opcua_collector.py  # 进场后实现
│   ├── s7_collector.py     # 备选
│   └── modbus_collector.py # 备选
├── uploader/
│   └── image_uploader.py   # 监听图片目录 → 压缩 → HTTPS 上传（视觉工控机）
└── writers/                # 下行指令写 PLC 的实现（与 collector 对应）
    └── ...
```

### 8.2 Mock 采集器要求（开发期最重要的一环）

Mock 数据要"像真的"，保证全链路验证有效：

- 六个关节角连续平滑变化（正弦叠加 + 小幅噪声），模拟真实运动周期
- 周期性切换状态：`running → idle → running`，偶发 `fault`
- 随机产生报警（低频率，如每 5~10 分钟一条）
- 视觉侧：从本地测试图片文件夹轮询发图，附带模拟 OK/NG 判定结果
- 支持 config.yaml 调节频率、报警概率等参数

### 8.3 断网续传

- MQTT 发布失败 → 写入本地 SQLite 队列（含时间戳）
- 连接恢复 → 按序补传，成功后删除
- 队列上限（如 50 万条 / 2GB），超限丢弃最旧并记日志告警

### 8.4 心跳与遗嘱

- 每 10s 发布 `factory/{lineId}/agent/heartbeat`，payload 含版本号、运行时长、队列深度
- MQTT 连接配置 LWT：异常掉线时 Broker 自动发布离线消息到 `agent/lwt`（retained）
- 云端根据心跳/LWT 维护 Agent 在线状态，前端可见

### 8.5 Windows 部署方式

```
C:\edge-agent\
├── agent.exe        # PyInstaller 打包（--onefile 或 --onedir）
├── config.yaml
├── cache\           # SQLite 离线队列

```


### 9.2 数字孪生实现要点（简化版）

- 机械臂模型：glTF 格式，按六个关节拆分节点（可用开源六轴机械臂模型起步）

- 视角控制：OrbitControls（旋转/缩放/平移）
- 状态着色：运行=绿 / 空闲=黄 / 故障=红

- 登录后拉取当前用户权限码列表，存 Pinia
- 路由守卫按权限拦截页面；按钮用 `v-if="hasPerm('line:control')"` 控制
- 所有数据仍以服务端过滤为准

## 13. 风险与对策

| 风险 | 对策 |
|---|---|
| 公网抖动导致数据丢失 | Agent 本地 SQLite 队列续传 + 关键数据 QoS1 |
| 公网安全暴露 | TLS + 每机凭证 + ACL + 可选 Tailscale 隧道 |
| PLC 协议与预期不符 | 采集层适配器模式，已隔离影响；进场前确认点表 |
| 高频时序数据撑爆数据库 | 入库降采样 + TimescaleDB 压缩与保留策略 + 连续聚合 |
| 误操作控制产线 | 权限最小化 + 服务端校验 + 二次确认 + 全量审计 + 急停纯硬件 |
| 图片带宽过大 | Agent 端压缩 + 限流 + 闲时上传策略 |
